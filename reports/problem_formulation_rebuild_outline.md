# Problem Formulation：从系统演化出发的全新结构

本轮按 ars-outline 设计论证结构，并按作者“直接重写”的要求据此替换英文正文。旧版段落和组织顺序不作为写作底稿；实现、方法接口和实验事实仍作为不可改变的依据。未指定投稿 venue，故不作 venue-fit 认证（criteria_binding_unavailable）。

## 核心逻辑

有限资源如何配置 → 配置如何产生收益与调整成本 → 历史结果如何形成风险成本 → 决策者能观察什么 → 在什么约束下优化政策。

采用“系统模型—演化规律—约束目标”的工程论文写法。CMDP 放在变量和动态已明确之后，作为问题的数学汇总。投资组合在收益与风险模块中实例化一般配置问题，不再另设一个包揽所有公式的实例小节。

## 2.1 Allocation System

**中心论点：** 决策变量是 N 维归一化配置；本项目处理两个可重叠组的最低配置要求。

- 定义决策时域、实体、动作和标准单纯形，N 仅表示坐标数。
- 直接定义实际支持的两组可行集；用补集说明上限如何转为下限。
- 非空性作为给定约束的假设；固定集合和阈值留在附录。
- 不在此讲 softmax、采样密度、CAOSD 分支或 PPO。
- 衔接：可行性确定可执行动作，动作价值由之后的系统演化确定。

**证据：** CAOSD §3；PASPO §3；simplex.py 的两组定义。约 140–180 个英文词。

## 2.2 Portfolio State Evolution

**中心论点：** 在投资组合实例中，目标配置、外生收益和配置调整共同决定净增长。

- 统一时序：观察 → 配置 → 收益实现 → 财富与风险更新。
- 给出目标权重换手、净增长、对数奖励与财富更新。
- 把目标权重成本代理作为执行模型的明确假设，区分严格持仓级自融资核算。
- 保留实际数值下限；具体数值、偿付能力充分条件与未建模摩擦留在附录。
- 衔接：财富递推给出定义路径风险所需的量。

**证据：** env.py:915 附近的实际交易记账；env.py:473 附近的财富更新；Jiang et al. §2.2–2.3。约 160–210 个英文词。

## 2.3 Benchmark-Referenced Path Risk

**中心论点：** 风险成本来自当前回撤超过已实现 benchmark 阈值的程度，预算随 benchmark 路径调整。

- 定义财富峰值、当前回撤、最大回撤和 benchmark 的对应量。
- 将阈值、平方超限成本和成本容忍度分开定义。
- 明确当前成本评价当前回撤；最大回撤仅作为诊断和评估量。
- 强调下一步阈值用于该步收益实现后的转移计费，不提前进入当前决策。
- 衔接：这些历史统计量必须进入完整状态，才能使成本成为转移函数。

**证据：** _benchmark_drawdown_components、_drawdown_components、V2.6/V3.2 配置。风险定义忠实于本项目，不移植 CVaR、机会约束或闭环风险投影。约 160–210 个英文词。

## 2.4 Information Structure and Policy Objective

**中心论点：** 完整状态保留配置与风险记忆，策略只接收有限市场特征和诊断；优化同时包含动作支持约束与期望平均成本约束。

- 显式给出完整状态及 portfolio 路径记忆，说明旧配置为何影响当前成本。
- 正确列出 actor 输入：历史收益、均值、波动率、旧权重、换手、组暴露与 slack、回撤诊断、时间。actor 不接收绝对财富或财富比率。
- 区分完整状态的 Markov 假设与观测的部分可观测性。
- 在上述变量之后定义 CMDP、初始分布、非前视策略及硬可行政策类。
- 奖励采用折扣累计值；成本统一采用固定时域平均值，与本项目的风险预算口径一致。
- 用一个一般约束优化问题汇总；portfolio 实例令转移成本为 c-alpha、固定预算为零。随机 allowance 留在期望内。
- 风险控制算法、折扣 GAE 近似、自回归分支及 CF 留在方法部分。

**证据：** _get_observation、状态结构、RCPO rollout 平均残差；CPO 的 CMDP 框架。约 260–330 个英文词。
